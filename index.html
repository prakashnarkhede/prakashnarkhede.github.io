Case Studies

Building an In-house AI Test Generation Platform

Problem

Test design consumed 30-40% of the team's sprint capacity, leaving less time for actual testing.

Approach

I built a RAG platform, deployed on Databricks, using hybrid retrieval to generate test scenarios, cases, and code from requirements and metadata. All output requires human review.

What I Would Do Differently

I underestimated index maintenance. Next time, I'd build an automated pipeline to refresh the index on requirement updates instead of batch processing.

Outcome

Achieved 80%+ generation accuracy, reducing test design cycle time by 30-40%. The platform is now the standard design path.

Testing Non-deterministic AI Agents

Problem

Product teams shipped LLM agents, and traditional deterministic assertions couldn't distinguish "factually wrong" from "differently worded but correct."

Approach

I split evaluation: factual correctness uses deterministic comparators against systems of record. Subjective qualities use LLM-as-judge with rubrics. Only deterministic checks gate releases.

What I Would Do Differently

I spent too long writing rubrics without failure data. I should have shipped a minimal rubric, collected production failures, and refined criteria.

Outcome

Strategy implemented for three LLM agents. Zero false-positive release blocks from the AI-graded lane.

Agentic Tooling for Test Authoring

Problem

Engineers manually applied testing conventions. Inconsistent compliance led to reviewer burn-out and slow PRs.

Approach

I embedded planner, generator, and reviewer agents into the IDE. The reviewer strictly enforces project conventions and metadata. Generated code requires human approval.

What I Would Do Differently

The reviewer agent is slow (adds ~15s) because it re-reads convention docs. I should have cached parsed conventions.

Outcome

Convention compliance exceeded 90%. Review comments dropped by half. Saving 80% time of automation engineers.

Automation Platform Evaluation and ROI Case

Problem

We ran three disjointed tools (TOSCA, Copado CRT, custom Selenium) with high maintenance overhead and no unified reporting.

Approach

I structured a multi-vendor evaluation with hands-on POCs for our hardest scenarios (multi-org Salesforce, API chain, UI regression). Built an 18-month ROI model.

What I Would Do Differently

I built the POCs myself, reflecting my proficiency. Next time, I'd have junior/mid-level engineers test ramp-up times independently.

Outcome

Projected 35% reduction in effort. Leadership approved the platform decision based on Salesforce metadata API coverage, not lowest cost.

Execution Report Consolidation & AI Analysis

Problem

We ran 10,000+ tests daily across Copado CRT and TOSCA. Analyzing failures meant logging into multiple tools, making triage a massive manual effort.

Approach

I built a consolidation pipeline that ingests daily runs into a single dashboard. Added automated failure categorization using rule-based logic and AI to tag root causes, with summaries delivered directly to Slack.

What I Would Do Differently

I should have standardized error messaging across teams earlier. We spent too much time tuning the AI to recognize custom error strings that could have been uniform.

Outcome

Reduced manual daily analysis effort by 80%+. Teams now get actionable failure insights in Slack before standup.
